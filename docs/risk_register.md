# Risk Register

| # | Risk | Likelihood | Impact | Mitigation implemented | Residual risk |
|---|---|---|---|---|---|
| 1 | Model underestimates lead-time variance (bad historical data) → safety stock too low → stockouts of critical items | Medium | High (patient safety) | Reliability mixture model widens effective lead-time variance beyond naive mean/std; `target_service_level` is stakeholder-set, not hardcoded; test `test_higher_service_target_increases_safety_stock` proves sensitivity | Requires periodic recalibration against real supplier data (see User Guide §5) |
| 2 | Supplier reliability data is stale or supplier behavior changes suddenly (e.g. new geopolitical/logistics disruption) | Medium | High | `test_case_1` and `test_case_3` explicitly simulate near-total reliability collapse and show the model degrades gracefully rather than silently; cost of degradation is visible in `total_cost`, prompting manual review | Model reacts to *configured* reliability, not real-time; needs an operational trigger to re-run when a supplier incident occurs |
| 3 | Over-ordering short-shelf-life items causes financial and clinical waste (e.g. platelets) | Medium | Medium-High | Expiry guardrail caps order-up-to quantity to ≤80% of shelf-life-feasible consumption (`policy_probabilistic.py::compute_probabilistic_params`); demonstrated on `PLT-CON-06` in the experiment (66.7% waste reduction vs baseline) | Guardrail is a heuristic (80% factor); should be tuned per clinical category with pharmacy input |
| 4 | Large orders overwhelm receiving staff, creating unsafe manual-handling conditions or shortcuts (mis-shelving, skipped checks) | Low-Medium | Medium (staff safety, data integrity) | Hard `WorkforceConfig.daily_receiving_capacity` ceiling in the simulator; overflow is **deferred**, never force-processed (`test_case_4_workload_overflow_is_deferred_not_dumped`) | Deferral itself delays availability; if it happens often, it signals `max_units_per_order` or staffing needs re-tuning |
| 5 | Fairness: policy could implicitly prioritize high-value/low-cost SKUs over clinically critical low-volume ones if only cost is optimized | Medium | High (equity of care) | Service-level target and stockout cost are set **per SKU**, independent of unit cost; EOQ only governs order *quantity*, not whether a critical SKU is stocked at all | Requires stakeholders to deliberately set higher `target_service_level` / `stockout_cost_per_unit` for clinically critical items — not automatic |
| 6 | Simulation is a simplification (single-SKU, no substitution effects, no multi-echelon transfers between wards/hospitals) | High | Low-Medium | Explicitly scoped and documented (see Stakeholder Assumptions); architecture keeps policy/simulation modular so multi-SKU/multi-echelon extension is possible later | Real deployment needs a pilot period comparing simulated vs actual outcomes before full rollout |
| 7 | Random-number-driven results could be mistaken for guarantees | Low | Medium | All experiment outputs report mean **and** std. dev. across 200 replications (`experiment_raw.csv`); error analysis table compares target vs measured service level | Stakeholders must be briefed that these are probabilistic targets, not guarantees |
| 8 | Numerical edge cases (zero demand, extreme variance) could crash the system in production | Low | Medium (operational availability) | `test_case_2` (demand surge) and `test_case_6` (near-zero demand) explicitly assert no NaNs/negative values/exceptions | New untested parameter combinations should be added to the test harness before go-live |
| 9 | Safety-stock formula assumes Normal-shaped demand-during-lead-time uncertainty; real demand for some items is not Normal (e.g. rare/low-volume drugs are count-like, some items are right-skewed) | Medium | Medium | `experiments/run_sensitivity_analysis.py` explicitly tests Poisson, Gamma, and Empirical (real historical log) demand shapes; confirms the policy's *qualitative* advantage over baseline holds in all three (see `docs/sensitivity_analysis.md`) | For very low-mean items (mean < ~1 unit/day) the Normal-based formula can be conservative (over-orders) since it can't represent Poisson's sharp floor at zero; a distribution-aware safety-stock formula for ultra-low-volume SKUs is a natural next refinement, not yet implemented |
| 10 | A code change could silently break the policy math or simulation logic without anyone noticing until a demo/review | Low | Medium | GitHub Actions CI (`.github/workflows/tests.yml`) runs the full test harness, the main experiment, and the sensitivity analysis automatically on every push/PR across 4 Python versions | CI only catches what the test harness covers; new features still need matching new tests |
